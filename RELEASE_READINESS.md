# ШУРШ! — релизный чеклист первого публичного бета-запуска

Обновлено 19 ноября 2026. Источник состояния: GitHub PR #1, GitHub Actions,
настройки Vercel (без чтения секретов), Supabase project health/security advisors.
Это не разрешение на merge или Production deploy.

## Объём первой версии

- Регистрация с подтверждением email; вход, выход, персональные сессии
- Личные и публичные вишлисты; добавление/изменение желания
- **Только ручная ссылка** на магазин; название и цена вводятся вручную
- Необязательное фото с устройства; резервирование подарков по приватным ссылкам
- Тайный Санта: приглашения, исключения, жеребьёвка, личные результаты
- Респонсивная версия на мобильном; понятные ошибки

Отложено: импорт цен/фото по ссылкам, платные API, партнёрские каталоги,
уведомления и сложная монетизация. Серверная точка product-preview
выключена; экспериментальные адаптеры не вызываются приложением.

## Настройки окружений — блокеры релиза

По чтению *метаданных* Production Vercel project `shursh`
на момент аудита присутствуют только:
`SUPABASE_URL`, `SHURSH_AUTH_REDIRECT_URL`.
Не хватает Production-ключей:
- `SHURSH_DATABASE_URL` — TLS pooler PostgreSQL под выделенным
  минимально привилегированным пользователем
- `SUPABASE_PUBLISHABLE_KEY` — публичный/publishable ключ, не service-role
- `SHURSH_RATE_SECRET` — отдельный случайный секрет Production

Все секреты должны добавляться в Vercel Environment Variables
непосредственно. Не писать их в исходниках, GitHub PR, CI-логи или переписку.
Проверить права БД и миграции, точный auth redirect URL, рабочую SMTP-доставку,
квоты, защиту и корректное отображение проблем регистрации.

Supabase `Shursh` на момент аудита: `ACTIVE_HEALTHY`.
Security Advisor: warning `auth_leaked_password_protection` — функция
проверки скомпрометированных паролей выключена.
Документация: https://supabase.com/docs/guides/auth/password-security

Vercel API ранее возвращал дневной лимит `api-deployments-free-per-day`.
Нельзя автоматически поднимать тариф или превышать лимиты.

## Публикация — только после явного разрешения владельца

1. Повторить проверку HEAD, PR Draft, CI и защищённого Preview
2. Зафиксировать целевой commit SHA и точку отката
3. Подтвердить Production env names/права/SMTP/URL и план резервного копирования
4. По отдельному разрешению: merge согласованным способом и Production deploy
5. HTTP + браузерный smoke на `https://shursh.vercel.app/`:
   вход, создание списка, пожелание со ссылкой, гостевая бронь и Тайный Санта
6. Проверка логов (без персональных данных и секретов), доступности
   со смартфона, регистрации другого пользователя и публичных ссылок
7. При критическом дефекте — остановить приглашения, выполнить откат
   после оценки совместимости схемы БД и сохранности созданных данных

До выпуска: **ветка `feat/supabase-mvp`, PR Draft, без merge и Production deploy**.
